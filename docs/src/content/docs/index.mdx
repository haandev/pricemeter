Tarifeyi ve şimdiye kadarki kullanımı sen verirsin; kütüphane tutarı hesaplar ve yazılacak **planı** döner. *Ne zaman*, *nerede*, *kim* — sayma, saklama, takvim, tampon, kuyruk, bakiye, HTTP, UI — senin uygulamanda kalır.

<CardGrid>
  <Card title="Üç model" icon="seti:config">
    `graduated`, `volume` (`on_crossing` düzeltmeli), `package`. Kademe başına `per`, sabit ücret, gözlem başı taban/tavan, `per_event_up` ya da sapmasız `cumulative` yuvarlama.
  </Card>
  <Card title="Saf çekirdek" icon="approve-check">
    `rate()` ve `price()` I/O yapmaz. `observe` ince bir sarmalayıcıdır: `getRate` → `price` → `commit`.
  </Card>
  <Card title="Hold" icon="puzzle">
    Çok satırlı rezervasyon bir değer nesnesidir: kısmi capture, extend, release. Tarife hold'un içinde saklanır.
  </Card>
  <Card title="Tipli katalog" icon="seti:typescript">
    Sayaç id'leri, boyutlar (zod / valibot / arktype, Standard Schema), havuzlar (`feeds`) derleme anında denetlenir. 500 sayaçlı katalog ~0,6 sn'de tip denetiminden geçer.
  </Card>
</CardGrid>
